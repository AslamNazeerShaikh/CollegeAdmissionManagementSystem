Yes. These screenshots are actually **very good reference material for an LLM-driven UI recreation** because they show multiple states of the same app rather than just one static screen.

The right approach is **not** to tell the LLM “make it look like this screenshot.” That usually produces something vaguely similar.

Instead, give the LLM:

1. **all six screenshots as visual references**
2. a **design-system specification**
3. a **layout specification**
4. a **component/state specification**
5. explicit instructions about **what must NOT change**
6. instructions to **measure proportions from the references rather than inventing a new design**

Below I've converted what I see in the screenshots into a reusable **UI/UX reverse-engineering prompt**.

# 2. The visual language I would extract

The screenshots have a very specific feel.

## Overall style

Think:

> **modern macOS business application + Linear-like cleanliness + Apple-style restraint + soft SaaS CRM UI**

Not:

* Material UI
* Bootstrap
* enterprise Angular
* overly rounded “AI SaaS”
* dark/neon startup
* glassmorphism
* excessive shadows

The design is **quiet, soft, spacious and functional**.

# 4. Borders

This is one of the most important characteristics.

The UI does **not** use heavy borders.

Use:

```text
border: 1px solid rgba(0,0,0,0.08)
```

or equivalent neutral gray.

Typical visual weight:

```text
1px
```

Never:

```text
2px dark border
```

unless used for a deliberate focus state.

Inputs, cards, tables, buttons and modals all use **very subtle boundaries**.

---

# 5. Corner radii

The screenshots consistently use rounded corners.

Approximate scale:

```text
App window:        18–22px
Large modal:       16–18px
Cards:              12–14px
Inputs:             8–10px
Buttons:            8–10px
Status pills:       999px
Avatars:            50%
```

Important:

> Don't make everything `border-radius: 20px`.

The hierarchy should be visible.

---

# 6. Shadows

The shadows are extremely subtle.

Think:

```css
box-shadow:
  0 1px 2px rgba(0,0,0,0.03),
  0 8px 24px rgba(0,0,0,0.06);
```

For modal:

```css
box-shadow:
  0 20px 60px rgba(0,0,0,0.12);
```

For drawer:

```css
box-shadow:
  -12px 0 40px rgba(0,0,0,0.08);
```

Not:

```css
box-shadow: 0 10px 30px black;
```

The application should feel **soft and elevated**, not floating dramatically.

## One final point

These screenshots are good enough to reproduce the **design language and interaction structure very closely**, but an LLM cannot reliably derive truly **pixel-perfect values** for every dimension from screenshots alone. For true pixel-level matching, the ideal workflow is:

**screenshots → initial implementation → screenshot of implementation → visual comparison → iterative correction**

That gives the model an actual feedback loop rather than asking it to estimate everything once. 🎯
